## Mismatches

1. **muse** — bar width is REMAINING (`row.limit - row.used` fraction, `MuseQuotaBody.tsx:32-34`), but the printed number reads `"{{percent}}% used"` using the USED value (`MuseQuotaBody.tsx:31,36-37`, i18n key `muse_quota.used_percent`). A short bar (little remaining) sits next to a number the user reads as "how much I've used," which happens to look numerically similar only when `used ≈ 100 - remaining`; the wording itself is the wrong axis relative to what the bar visually encodes.
2. **xai, weekly limit row** — bar is REMAINING (`weeklyRemaining`), printed text is `"Used {{percent}}"` computed from `weeklyUsed` (`XaiQuotaBody.tsx:105/137-139/146`).
3. **xai, per-product usage rows** — bar is REMAINING (`remainingPercent`), printed text is `"Used {{percent}}"` computed from `used` (`XaiQuotaBody.tsx:152/161-163/167`).

All other providers (antigravity, claude, codex, cursor, kimi, ollama, and xai's pay-as-you-go row) pass the *same* remaining-based variable to both the bar and the printed number, so bar and text agree numerically — though claude, codex, cursor, kimi, and ollama print a bare `${value}%` with no i18n wording key at all (no "remaining"/"used" word appears on screen), so the agreement is by shared arithmetic only, not by an explicit label confirming the axis.
